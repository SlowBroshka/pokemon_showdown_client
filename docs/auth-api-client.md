# HTTP-клиент авторизации

Задача: [#19](https://github.com/SlowBroshka/pokemon_showdown_client/issues/19).
Третий пункт этапа C2, по [контракту авторизации](auth-contract.md).

## План и реализованный объём

Один PR: типизированный HTTP-клиент → проверка запроса/ответа → ограничения
и отмена → тесты на fixtures и управляемом адаптере → документация API.

Реализован `lib/core/auth/auth_api_client.dart` без зависимости от Flutter.
Он получает имя, пароль и полный challenge, затем возвращает `AuthLoginResult`
либо бросает `AuthException` с категорией `AuthFailure`.
Модели и enum вынесены в отдельные файлы. `http` 1.6.0 закреплён в lockfile.

Полученный результат означает только успешную проверку HTTP-ответа.
Он не подтверждает личность на игровом сервере. Вызов `/trn`, ожидание `updateuser`,
поколение соединения и ID попытки входа реализованы в [AuthController](auth-controller.md).
Текущий экран подключения не изменён, сетевых вызовов при старте не добавлено.

## API и владение

```dart
final api = AuthApiClient();
try {
  final result = await api.login(
    username: username,
    password: password,
    challstr: challenge,
  );
  // Перед использованием result.assertion контроллер проверяет актуальность
  // поколения соединения, challenge и ID попытки входа. Не логировать result.
} on AuthException catch (error) {
  // Переводить error.failure в UI; исходного текста сервера здесь нет.
} finally {
  await api.dispose();
}
```

`AuthLoginResult` неизменяем, содержит `username` (каноническое написание ответа),
`userId` и `assertion`. Его toString скрывает все значения. У результата нет
флага authenticated, поскольку HTTP не заменяет подтверждение через WSS.

Один экземпляр обслуживает одну незавершённую попытку. Конкурентный login или login
после dispose — ошибка использования API (`StateError` без входных значений).
Обычные отказы имеют типизированную категорию, без исходного исключения/JSON.

Каждая попытка создаёт собственный `http.Client` и закрывает его в finally.
Не используются общий cookie jar, браузерная сессия и сохранение Set-Cookie.
Точка внедрения `clientFactory` предназначена для доверенного тестового адаптера:
он должен возвращать новый клиент, поддерживающий abort, и не вести журнал секретов.
Передавать клиент, используемый другими компонентами, нельзя: владение передаётся
одной попытке. В production используется штатный нативный клиент пакета http.

`cancelPending()` завершает ожидающий login категорией cancelled и сигнализирует
abort текущему запросу. Перед новой попыткой дождаться завершения предыдущего login.
`dispose()` также отменяет запрос, запрещает последующие попытки и возвращает Future
завершения локальной очистки. Повторный dispose безопасен. Ошибки закрытия адаптера
не выводятся наружу; стандартный HTTP-клиент закрывает принадлежащие ему соединения.
Таймаут охватывает и получение заголовков, и чтение всего тела. Поздний ответ
отменённой операции не возвращается как результат следующего запроса.

## Запрос и валидация

Endpoint фиксирован:
`https://play.pokemonshowdown.com/~~showdown/action.php`.
Пользовательский WSS-адрес не влияет на него. POST-тело form-urlencoded содержит
только `act=login`, `name`, `pass`, `challstr`. Пароль не обрезается; пробелы,
Unicode и специальные символы кодируются стандартным механизмом Request.bodyFields.
Имя и challenge не подставляются в URL. Перенаправления запрещены для всех 3xx,
включая переход на тот же хост. Запасной endpoint и автоматические повторы отсутствуют.

Для первой версии имя — непустое ASCII до 18 символов, без пробелов по краям,
управляющих символов, `|`, запятой и `;`. UserId вычисляется удалением всего,
кроме строчных a–z и цифр; он не может быть пустым. Это локальное ограничение
совместимости, не попытка заменить серверные правила имён. Пустой пароль запрещён.
Challenge — до 4096 символов, цифровой keyid + `|` + непустой хвост без пробелов
и управляющих символов; внутренние разделители хвоста сохраняются.
Ошибочный ввод даёт invalidInput до создания сетевого клиента.

HTTP-статус проверяется до чтения тела. Для 200: строгий UTF-8 → префикс `]` →
JSON-объект → поля отказа → curuser.loggedin строго true → username с тем же userId
→ непустой безопасный assertion. Content-Type не обязан быть application/json.
Неизвестные дополнительные поля игнорируются; неправильные типы обязательных полей
отвергаются. `error`/`actionerror` со строкой имеют приоритет над полями успеха,
даже если в ответе есть assertion. Неверный тип поля ошибки даёт invalidResponse.

Assertion остаётся непрозрачной строкой: подпись клиентом не проверяется.
Запятые и `;` внутри допустимы; пустота, пробелы по краям, ведущий `;`, `<`, `|`,
управляющие символы и разделители строк отвергаются. HTML не исправляется и не
отображается. Сырые ошибки сервера и произвольные поля не попадают в результат.

| Категория | Значение |
|---|---|
| invalidInput | Неподдержанный ввод до сетевого запроса |
| network / timeout / cancelled | Сетевая ошибка, истёкший общий срок или явная отмена |
| unexpectedRedirect | Любой HTTP 3xx, без следования Location |
| rateLimited / serviceUnavailable / httpFailure | HTTP 429, 5xx либо иной статус, кроме 200 |
| invalidResponse | Неверный UTF-8, оболочка, JSON, типы или другая личность |
| responseTooLarge | Превышен лимит по Content-Length либо фактически прочитанным байтам |
| loginRejected | Поле отказа либо curuser.loggedin == false; это не обязательно неверный пароль |
| invalidAssertion | Непригодная для отправки в протокол строка assertion |

По умолчанию срок 15 секунд, максимум ответа 64 КиБ. Лимит проверяется на потоке,
включая ответы без Content-Length; тело сверх лимита не накапливается в памяти.
Параметры timeout и maxResponseBytes можно изменить в конструкторе, но они
должны быть положительными. Пароль и assertion не сохраняются на диск; очищение
ссылок не гарантирует физического обнуления памяти строк Dart.

## Проверки и оставшаяся интеграция

`test/core/auth/auth_api_client_test.dart` проверяет все 17 login-примеров из
подготовленного HTTP-корпуса, а также кодирование тела, точный адрес, отсутствие
redirect/retry/cookie reuse, схему/личность/assertion, байтовые границы, ошибки
UTF-8 и сети, таймаут до заголовков и при непрерывном потоке, отмену и disposal.
Оставшийся 18-й пример описывает upkeep, который не входит в этот API.

Запуск: `flutter test test/core/auth --concurrency=1`.
Тестовые адаптеры возвращают синтетические ответы; реальные имена, пароли,
cookies и подписи не используются. Тесты не обращаются к публичному серверу.
Источники и анонимная проверка endpoint находятся в auth-contract.md.

**Успешный вход зарегистрированным тестовым аккаунтом всё ещё не проверен.**
Нужно отдельно подтвердить выбранный endpoint и схему успешного live-ответа,
а затем полный обмен /trn → updateuser на Android/Linux. В этом PR не реализованы
UI входа, session upkeep/logout, secure storage или управление WSS-соединением.
