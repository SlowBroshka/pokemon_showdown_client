# Интерфейс входа

Задача: [#23](https://github.com/SlowBroshka/pokemon_showdown_client/issues/23).
Пятый пункт этапа C2: интерфейс для готового [AuthController](auth-controller.md).

## План одного PR и результат

1. Блок аккаунта с именем/паролем, показом пароля, входом и отменой.
2. Подключение общего контроллера, отображение ожидания и подтверждённой личности,
   выход с отключением и очисткой локального состояния.
3. RU/EN для всех состояний и ошибок; русский по умолчанию.
4. Сквозные UI-тесты, узкий экран/крупный текст/клавиатура, снимок компоновки.
5. Проверки проекта и сборок Android/Linux, документация и связанный PR.

Блок реализован в `lib/features/auth/auth_panel.dart` и включён в штатный экран
подключения. Вход HTTP/WSS сам по себе не выполняется при запуске приложения:
сначала пользователь подключается и явно вводит данные существующего аккаунта.
Одна активная комната и ручное управление соединением сохранены.

## Действия пользователя

Подключиться к основному серверу, дождаться готовности, заполнить имя и пароль
и нажать «Войти в аккаунт». Во время HTTP-запроса и подтверждения поля/повторный
вход недоступны, доступна «Отменить вход». Пароль скрыт; кнопка с подсказкой
позволяет показать/скрыть его. Пустые поля не отправляются, Enter соблюдает ту же
проверку, что и кнопка. Пробелы по краям имени убираются в UI; пароль не изменяется.

HTTP-ответ не показывает успешный вход: до подходящего updateuser выводится
ожидание подтверждения игровым сервером. После него отображаются подтверждённое
имя и «Выйти и отключиться». Можно войти в одну комнату, выйти из неё и отключиться.
Выход очищает подтверждённую личность и поля формы, закрывая WSS.
Это локальный выход; отзыв HTTP-сессий на других устройствах не реализован.

Отказ HTTP отображается безопасной категорией. Для повтора нужно заново ввести
пароль и явно нажать кнопку. Сырые ошибки сервера, HTML, challenge и assertion
не отображаются. Отмена до /trn сохраняет WSS, после /trn требует отключения —
правило контроллера отображается через его состояния. При потере связи пароль
стирается, а подтверждённое имя исчезает. Самопроизвольного повторного входа нет.

Авторизация на произвольном WSS пока недоступна: поля заблокированы, показано
объяснение. Диагностический вход в комнаты остаётся доступен по прежним правилам.

## Секреты и владение

Пароль очищается сразу после передачи в контроллер, при отмене и при переходах
из готового состояния (в том числе при отключении). Показ пароля сбрасывается.
Закрытие формы освобождает её TextEditingController и подписку. Имя может оставаться
в памяти формы для явного повтора после сетевой ошибки; «Выйти и отключиться»
очищает и его. На диск поля не сохраняются. Физическое обнуление памяти строк Dart
не гарантируется.

AuthPanel владеет только состоянием формы. Общий AuthController и сессия остаются
во владении MyApp; снятие экрана не уничтожает их. ConnectionScreen принимает
необязательный authController вместе с внешним connection controller. В штатном
приложении оба используют одну сессию. Самостоятельный диагностический экран
без authController сохраняет прежний сценарий без блока аккаунта.

## Локализация и доступность

Все новые строки находятся в обоих ARB; AppLocalizations генерируется стандартно.
`auth_message_localization.dart` исчерпывающе сопоставляет AuthPhase и AuthFailure
с переводами. Подтверждённое имя передаётся параметром ARB, без склеивания текста.
Сообщения состояния/ошибок имеют live-region semantics, показ пароля — локализованную
подсказку. Поля используют режим без автокоррекции/подсказок; для пароля отключено
персонализированное обучение IME. Переключатель языка и регистрация не добавлены.
Общий ListView прокручивается при клавиатуре и увеличении текста; кнопки используют Wrap.

## Проверки

`test/features/auth/auth_panel_test.dart` использует реальные контроллеры,
AuthApiClient и ShowdownTransport с управляемыми HTTP/WebSocket-адаптерами.
На RU/EN проверяется весь путь: подключение → challenge → ввод → HTTP → /trn →
updateuser → вход/выход комнаты → выход с отключением. Отдельно проверяются
отказ/повтор, отмена, поздний ответ, очистка видимого пароля, отсутствие HTTP на
неподдержанном сервере, повторные нажатия, Enter, отказ игрового сервера, переводы,
экран 320×640 при масштабе текста 200% и имитации экранной клавиатуры.

Запуск: `flutter test --concurrency=1`.
Для визуальной проверки: `flutter test test/features/auth/auth_panel_test.dart
--plain-name 'capture account layout when requested' --dart-define=CAPTURE_AUTH=true
--dart-define=CAPTURE_FONT=/absolute/path/to/font.ttf`. Снимок сохраняется в
`/tmp/showdown-auth-ui.png`; используются только синтетические данные.
Сборки Android/Linux проверяются в CI, последовательно выполняемые локальные
тесты не требуют публичной сети или реальных учётных данных.

### Проверка с публичным сервером

25 октября 2026 года, 15:15 UTC, с разрешения владельца выполнен реальный вход
тестовым аккаунтом. Штатные AuthController, AuthApiClient и ShowdownSession
запущены под Linux: получен challenge, выполнен HTTPS-вход, отправлен /trn,
личность подтверждена через updateuser. Сервер подтвердил вход в комнату `help`
и выход из неё; после отключения WSS подтверждённая личность очищена.
Учётные данные переданы только в память проверочного процесса через stdin
с отключённым эхом. Имя, пароль, challenge, assertion и cookies в отчёт не включены.

Это проверка сетевого слоя, без запуска интерфейса на устройстве. Сборки Android
и Linux, анализ и тесты прошли в [CI](https://github.com/SlowBroshka/pokemon_showdown_client/actions/runs/40205538935)
для коммита `73c91ae`. Ручная приёмка собранного приложения на Android/Linux
остаётся: вход до подтверждённого имени, вход/выход комнаты и отключение;
отдельно — неверный пароль, отмена и потеря связи.
Сохранение сессии, cookie upkeep и HTTP logout остаются отдельным этапом.
