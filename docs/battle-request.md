# Типизированные боевые запросы

Задача [#27](https://github.com/SlowBroshka/pokemon_showdown_client/issues/27),
пункт 2 этапа «Минимальный бой». Основание: [контракт](battle-contract.md).

## План и результат PR

1. Неизменяемые модели запроса, своей стороны, Pokémon, HP/статуса и атак.
2. Разбор move/switch/wait/null, отдельные malformed/unsupported результаты.
3. Интеграция `BattleRequestEvent` в существующий декодер протокола.
4. Проверки 25 примеров корпуса, границ, неизменяемости и приватности ошибок.
5. Документация API и регрессионная проверка существующего проекта.

Все пункты выполнены. Модуль — чистый Dart, без новых пакетов, сети и Flutter.
Каждый класс/enum находится в отдельном файле.

## API

`decodeBattleRequest(String payload)` экспортируется из
`lib/core/battle/requests/battle_request_decoder.dart`. Вход — JSON-хвост после
`|request|`, не полное сообщение WebSocket. Результат — `BattleRequest`.

| Поле | Содержание |
|---|---|
| `kind` | noRequest, wait, move, switchRequest, malformedRequest, unsupportedRequest |
| `rqid` | Необязательный номер; не является локальной версией запроса |
| `noCancel` | Серверное ограничение; для wait всегда true; undo пока не реализован |
| `side` | ID/имя своей стороны и неизменяемый состав Pokémon с индексами с единицы |
| `active` | Атаки, trapped/maybeTrapped/maybeDisabled/maybeLocked, доступный Tera Type |
| `moveSlots` / `switchSlots` | Доступность только в рамках запроса, не разрешение отправлять команду |
| `canTerastallize` | Есть доступная атака и разрешённый сервером Tera Type |
| `reason` | Фиксированная категория ошибки без входного текста |

`RequestPokemon` сохраняет ident/details, HP, статус, active, moves/stats,
item/ability/baseAbility, teraType/terastallized. Отсутствующая строка — null,
явно пустые item/ability — пустая строка. Имена не используются как номера слотов.
Для `0 fnt` HP=0 и maxHp=null: максимум в строке отсутствует. Для живого Pokémon
требуется положительное hp/maxHp. Приватный HP отделён от публичной шкалы противника.
Списки и карты копируются в неизменяемые коллекции; сырой JSON в моделях не хранится.
Публичные конструкторы предназначены для доверенного кода; сетевые данные
обязательно проходят через декодер.

## Интеграция и замена запросов

`decodeServerRecord` создаёт `BattleRequestEvent` для каждого комнатного request,
в том числе с noRequest/malformedRequest/unsupportedRequest. Глобальный request
без roomId возвращается как `MalformedServerEvent`. Принадлежность комнаты
текущему бою проверит будущий контроллер.

Подписчик обязан **заменять** свой снимок на `event.request` при каждом событии,
включая ошибку или null; нельзя оставлять доступные кнопки от предыдущего запроса.
Повторный rqid не означает, что запрос не изменился. Декодер не хранит состояние:
каждый вызов возвращает полный независимый результат. Тесты проверяют изменение
доступности с одинаковым rqid. [BattleState](battle-state.md) теперь хранит request
и requestRevision. Очистка черновика, проверки перед отправкой и send — следующие PR.

Ошибка имеет пустые списки действий и не содержит side/active. Ошибка одного
события не мешает обработать следующее. Исходная record у события по-прежнему
содержит приватный request: её нельзя безусловно логировать. reason и стандартный
ToString не раскрывают payload. Исключения некорректного ввода не выходят наружу.

## Ограничения валидации

Типы не приводятся автоматически; обязательные поля и HP/PP проверяются до
выдачи действий. requestType необязателен, но при наличии должен соответствовать
сетевой форме. Неизвестные дополнительные поля игнорируются. Неизвестный
requestType, team preview, ally/targetable, multi-active, p3/p4, Mega/Z/Dynamax/Ultra,
revival и commanding дают unsupportedRequest.
Последние признаки сверены с
[серверной моделью](https://github.com/smogon/pokemon-showdown/blob/9b136a8c8cdb860a8ab96fa063f906604e352547/sim/side.ts#L89)
и [выбором замены клиента](https://github.com/smogon/pokemon-showdown-client/blob/ab4b77b8f3a5712e8fbe03ce106ef2b70a874fdb/play.pokemonshowdown.com/src/battle-choices.ts#L231):
они меняют смысл выбора слота, поэтому не обрабатываются как обычная замена.

Политика прототипа: максимум 262144 UTF-16 единиц в payload и 32 уровня JSON.
Превышение даёт malformedRequest; проверка глубины учитывает строки и экранирование.
Неотрицательные целые rqid/PP/stats ограничены 2^53−1. Размер исходного WebSocket
сообщения этими лимитами не ограничивается. Строгий поднабор контракта не равен
полной совместимости с любым сервером: например, строковый disabled отклоняется.
Поколение/режим из событий комнаты, результат боя и несовместимость поля проверит C5.

## Проверки

`flutter test test/core/battle/battle_request_decoder_test.dart` выполняет все
25 cases из requests.json через настоящий декодер. Дополнительные тесты проверяют
модели, стороны, статусы, типы, ограничения выбора, неизменяемость, лимиты,
обновление с тем же rqid и цепочку parser → event decoder.

Полная проверка 22 сценариев из scenarios.json ещё требует контроллера;
проверки проекции пяти сценариев теперь выполняются тестами BattleState.
Живой бой и отправка решений этим PR не проверяются.
