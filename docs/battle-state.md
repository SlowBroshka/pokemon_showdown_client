# События и минимальное состояние боя

Задача [#29](https://github.com/SlowBroshka/pokemon_showdown_client/issues/29),
пункт 3 этапа «Минимальный бой». Основание: [контракт](battle-contract.md).

## План и результат

1. Декодировать участников, метаданные, начало/ходы, switch/drag, move/cant,
   HP/статусы, faint, Tera и win/tie в типизированные события.
2. Добавить неизменяемый BattleState и чистую функцию последовательного применения.
3. Разделить наблюдаемое поле и последний приватный request без расчёта механик.
4. Проверить некорректные/неподдерживаемые события, порядок и терминальность.
5. Обновить API/контракт и выполнить регрессионные проверки.

Все эти части реализованы без новых зависимостей, сети и Flutter.
Каждый класс/enum вынесен в свой файл. Декодер подключён к decodeServerRecord,
но состояние пока не создаётся корнем приложения и не подключено к экрану.

## API и владение

`lib/core/protocol/battle_event_decoder.dart` экспортирует типы событий и
`decodeBattleEvent(ServerRecord)`: null означает чужой тип события,
MalformedServerEvent — повреждённое поддерживаемое событие. Обычный путь —
parseServerMessage → decodeServerRecord; отдельный декодер вызывается автоматически.
События сохраняют record/roomId, фиксированная причина ошибки не содержит payload.
Завершающие протокольные аннотации `[from]`, `[of]`, `[silent]` и другие сохраняются
в record, но не влияют на эту минимальную проекцию. Сырой record не логируется.

`lib/core/battle/state/battle_reducer.dart` экспортирует модели и функцию:

```dart
var state = BattleState(roomId: roomId, connectionEpoch: epoch);
state = reduceBattleEvent(state, event, connectionEpoch: sourceEpoch);
// При разрыве соединения:
state = state.markStale();
```

Передавать sourceEpoch из SessionUpdate, не текущий номер по догадке. Чужие комнаты,
глобальные события, другие поколения и события после stale игнорируются.
Новое соединение/новый контекст боя требуют нового BattleState. Автоматическое
восстановление и выбор владельца комнаты остаются будущей интеграцией.

## Содержимое снимка

- phase: uninitialized → initialized → started → finished/closed;
- title, generation, gameType, tier, players и teamSizes;
- active: один наблюдаемый Pokémon на p1/p2, ident, непреобразованный details,
  сообщённый HP/статус и раскрытый Tera Type;
- request, его локальная requestRevision, последний privateSide;
- result с именем победителя либо ничьёй, stale и липкий unsupported;
- ограниченный 200 записями структурированный журнал move/cant в порядке событий.

Карты и списки копируются в неизменяемые коллекции. Модели не хранят общий raw-log,
HTML или приватные сетевые строки. Журнал содержит только поля действия и номер
хода; локализация и отображение остальных событий относятся к UI.

BattleHealth хранит числитель/знаменатель ровно из публичного события: знаменатель
не объявляется точным максимумом HP, не дополняется справочником. Для `0 fnt`
максимум неизвестен. Событие faint устанавливает hp=0, сохраняя уже известную шкалу.
Приватный HP из request.side остаётся отдельным снимком на момент этого запроса;
публичные move/damage не вычисляют его новое значение и не уменьшают PP.

Каждый switch/drag заменяет текущий активный слот. Tera может быть раскрыта также
в details через `, tera:TYPE`. Резерв противника не восстанавливается по никнейму,
не моделируются item/ability, Illusion, Transform или скрытые длительности.
Событие об отсутствующем/неактивном Pokémon блокирует совместимость: клиент не
приписывает его другому объекту. Поддержка воздействий на резерв — будущая работа.

## Правила применения

- До init события поля не применяются; повторный init не сбрасывает уже существующий
  контекст и несовместимость. Для полного восстановления нужен новый экземпляр.
- Совместимый набор — gen=9, singles, p1/p2, по одному активному слоту a,
  teamSize 1–6. Tier хранится буквально и не доказывает поддержку формата.
- turn меняет номер, но не разрешает выбор. Уменьшение номера ставит unsupported.
- HP/status/Tera применяются к известному активному ident. Двухцелевой sethp
  проверяет обе цели до изменения: частичного обновления при ошибке нет.
- request заменяется целиком, включая null и malformed/unsupported запросы;
  requestRevision увеличивается даже при повторном rqid. Последний privateSide
  сохраняется отдельно как исторический снимок; смена его стороны блокируется.
- Неизвестное значимое событие, повреждённое событие или неподдерживаемый режим
  ставит unsupported. Следующий request эту отметку не снимает. Известные
  декоративные события игнорируются; HTML/uhtml не исполняются и не сохраняются.
- win/tie завершают бой и очищают request. Поздние request/start/init/turn не
  возобновляют его. deinit закрывает комнату, сохраняя уже известный результат.
  Закрытие и разрыв сами по себе не создают победу/поражение/ничью.

`compatible` означает только поддерживаемую проекцию gen9 singles. Это **не**
разрешение отправить ход: будущий контроллер обязан также проверить stale,
терминальность, актуальность request/поколения/sequence, доступность действия
и факт предыдущей отправки. Ошибки выбора и popup не подтверждают ход и не меняют поле.

## Источники и ограничения

Поля повторно сверены с закреплённым
[SIM-PROTOCOL](https://github.com/smogon/pokemon-showdown/blob/9b136a8c8cdb860a8ab96fa063f906604e352547/sim/SIM-PROTOCOL.md#receiving-messages):
участники, идентификаторы, details/Tera, действия и аннотации.
Публичный сервер не использовался. Это контролируемый прототип, а не поддержка
всех механик Random Battle. Нераспознанная форма HP/события блокирует совместимость.

## Проверки

Тесты покрывают типы событий, ошибочные поля, аннотации, порядок, неизменяемость,
раздельные HP и PP, атомарность sethp, сохранение результата, неизвестные события,
чужую комнату/поколение, stale и ограничение журнала.
Из scenarios.json исполняются **только проверки проекции** пяти сценариев:
status-and-hp, ordinary-turn, forced-switch, terastallize, tie-is-terminal.
Шаги choose/send/phase контроллера намеренно не проверяются этими тестами: это PR 4.
Полный интерпретатор 22 сценариев и живой сквозной бой ещё не реализованы.
