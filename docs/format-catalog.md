# Каталог форматов: план и API второго PR

Дата: 28 октября 2026 года. Основа — [контракт поиска](matchmaking-contract.md).
Задача: [#39](https://github.com/SlowBroshka/pokemon_showdown_client/issues/39).

## План и результат

1. Неизменяемые FormatCatalog и ShowdownFormat; отдельные enum для результата
   декодирования и причины доступности.
2. Чистый разбор formats: секции, колонки, локальный ladder, hex-флаги,
   канонические ID, обнаружение legacy и повреждения.
3. Фильтр единственного целевого формата gen9randombattle с явным включением
   экспериментального режима и объяснимыми причинами отказа.
4. Типизированное глобальное событие и app-owned контроллер каталога, созданный
   до подключения; замена снимков, сброс свежести, изоляция поколений соединения.
5. Подключение всех **17** formats-примеров корпуса к реальному декодеру,
   дополнительные проверки моделей, политики и жизненного цикла сессии.

Все пункты реализованы. Поиск, updatesearch, команды, UI и живая проверка
матчмейкинга остаются последующими PR. Миграция на Riverpod не нужна.

## Модели и декодер

`decodeFormatCatalog(data)` принимает payload после `formats|`; пустая строка
означает корректный пустой каталог. `FormatsEvent` создаётся для любого глобального
formats, включая повреждённый: потребитель обязан заменить прежний снимок.
Комнатное formats даёт MalformedServerEvent и не обновляет глобальный каталог.

`FormatCatalog.kind`: valid, malformed, legacyUnsupported. `formats` — защищённая
от изменений карта канонических ID; localLadder соответствует маркеру ,LL.
Повреждение возвращает пустую карту, даже если ранее в сообщении были корректные
записи. В смешанном modern/legacy каталоге записи сохраняются для диагностики,
но весь снимок имеет legacyUnsupported и поиск запрещён.

`ShowdownFormat` содержит id, исходное name, section, column и flags.
Флаги хранятся в BigInt: неизвестный старший бит не теряется из-за переполнения.
При legacy flags=null. Именованные getters раскрывают все документированные биты;
unsupported означает legacy, partner или неизвестные биты выше 0x100.
Одна неизвестная современная запись не блокирует другие корректные записи.

Уточнения строгой валидации: контрольные символы запрещены; hex должен быть целиком
валиден; колонка — десятичное неотрицательное число до 2147483647; пустой маркер
секции сохраняет прежнюю колонку. Дублированный ,LL, пустая/оборванная секция,
маркер вместо названия секции, пустой канонический ID или его дубликат делают весь
каталог malformed. Названия остаются текстом; HTML не исполняется этим слоем.

## Доступность

Чистая функция `formatAvailability(catalog, formatId:, fresh:,
experimentalEnabled: false)` возвращает одну причину, в следующем порядке:

| Результат | Условие |
|---|---|
| staleCatalog | Нет снимка или он не свежий |
| malformedCatalog / legacyCatalog | Снимок отвергнут |
| notAdvertised | Точный ID отсутствует |
| unsupportedFormat | ID вне allowlist gen9randombattle |
| unsupportedFlags | Неизвестные биты или partner |
| searchDisabled | Нет бита searchShow |
| teamRequired | Нет preset/random |
| experimentalDisabled | Экспериментальный режим явно не включён |
| experimental | Метаданные допускают экспериментальную проверку |

Входной formatId не нормализуется: UI должен использовать ID из модели.
`experimental` не означает подтверждение авторизации, свободную очередь,
отсутствие активного боя, гарантированный рейтинг или полную поддержку механик.
Эти условия проверит будущий контроллер поиска. bestOfDefault не запрещает
обычный поиск, а generic rated-флаг из каталога не выдумывается.

## Жизненный цикл

`FormatCatalogController(session:)` подписывается на общую ShowdownSession;
создан в корне приложения до подключения, освобождается до уничтожения сессии.
Контроллер не отправляет команды и не владеет сокетом.

- `catalog` — последний полученный снимок; для действий всегда использовать
  `availability()`, а не напрямую проверять карту.
- `fresh` проверяет connected, актуальный epoch, source sequence и завершение
  доставки всех записей frame через барьер event loop. Это не серверный ACK.
- Новый malformed/legacy/пустой снимок заменяет старый. События другой комнаты
  и старого epoch не меняют его.
- Начало нового подключения, disconnect и закрытие потока очищают каталог.
  Проверка живого состояния сессии запрещает доступность ещё до доставки статуса.
- Ранний каталог во время handshake сохраняется, но становится доступным лишь
  после успешного подключения. Позднее создание контроллера не переигрывает
  пропущенный каталог: нужно создавать его до connect.
- `changes` — broadcast уведомления без replay; потребитель читает текущее
  состояние. Уведомления о продвижении потока позволяют снять временную блокировку
  после доставки. Dispose идемпотентен и закрывает только собственные ресурсы.

## Проверки и ограничения

Тесты в test/core/matchmaking проверяют 17 formats-примеров, все поля заданных
ожиданий, секции/флаги, неизменяемость, строгую валидацию, большие флаги,
смешанный legacy, причины отказа, замену снимков, ранний каталог, room scope,
доставку нескольких обновлений в одном frame, source sequence, disconnect,
новый epoch и dispose. Остальные 17 примеров updatesearch и 34 сценария остаются
спецификацией следующих PR; они не считаются исполненными тестами поиска.

Полный локальный сервер и публичный matchmaking в этом PR не запускаются.

Локальные проверки: 30 новых тестов, полный набор — **331 passed**, 2 opt-in
сетевых теста пропущены. Анализатор без замечаний; форматирование 132 Dart-файлов
без изменений; diff и относительные ссылки проверены. Платформенные сборки
оставлены существующему CI, локально повторно не выполнялись.
