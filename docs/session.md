# Общая сессия подключения

Задача: [#17](https://github.com/SlowBroshka/pokemon_showdown_client/issues/17).
Второй пункт этапа C2, после [контракта авторизации](auth-contract.md).

## План и результат одного PR

1. Выделить `ShowdownSession`, владеющую одним транспортом и маршрутизатором.
2. Пронумеровать попытки соединения, сохранить порядок сообщений и lifecycle,
   проверять поколение перед отправкой команд.
3. Передать владение сессией корню приложения; внедрять её в контроллер экрана.
4. Сохранить одну активную комнату, действия подключения/отключения и RU/EN UI.
5. Проверить совместное использование, поздние события, повторное подключение
   и освобождение ресурсов. Подготовить API для будущего контроллера авторизации.

Все пять задач входят в этот PR. HTTP-вход, хранение секретов, автоматический
reconnect, навигационный пакет и изменение политики комнат остаются следующими
задачами. Сессия не хранит пароль, assertion или историю сетевых событий.

## Владение

`MyApp` создаёт `ShowdownSession` и `ConnectionController(session: session)`
в своём State. Экран получает готовый контроллер. При снятии экрана его владелец
продолжает держать контроллер и соединение; при закрытии приложения сначала
закрывается контроллер, затем сессия. Статус удалённого приложения при завершении
процесса не гарантирует серверный logout.

Контроллер с внедрённой сессией отменяет только свои подписки и таймер.
`controller.closed` подтверждает освобождение этих ресурсов. Контроллер без
внедрения создаёт собственную сессию для самостоятельного экрана и закрывает её.
Такой режим не применяется в корне приложения.

Сессия принимает необязательный транспорт для тестов, **принимая владение** им.
Передавать нужно отключённый транспорт, которым больше никто не управляет.
Нельзя отдельно вызывать его connect/disconnect/dispose после передачи сессии.
`session.dispose()` идемпотентен, отменяет незавершённое подключение, закрывает
маршрутизатор/транспорт/потоки и навсегда запрещает новое подключение.
Подписчикам следует отменять свои подписки перед закрытием владельца; приостановленная
подписка может задерживать завершение Stream.close по обычным правилам Dart.

## API

Реализация: `lib/core/session/showdown_session.dart`, без зависимости от Flutter.

| API | Назначение |
|---|---|
| `connect(Uri)` / `disconnect()` | Явное подключение/отключение без автоматического повтора |
| `status` / `statuses` | Текущее состояние и последующие изменения актуального поколения |
| `connectionEpoch` | Номер принятой попытки соединения, начиная с 1; до первой попытки 0 |
| `endpoint` / `latestUpdateSequence` | Адрес принятой попытки и номер последнего изменения на источнике до доставки подписчикам |
| `isCurrent(epoch)` | Поколение активно и совпадает с текущим; connecting тоже считается активным |
| `updates` | Упорядоченный поток SessionUpdate со статусом либо событием и номером его исходного поколения |
| `globalEvents` / `roomEvents` / `eventsForRoom(id)` | События с номером поколения; устаревшие отсекаются при доставке |
| `rooms` / `roomChanges` | Неизменяемый реестр комнат и его снимки из маршрутизатора |
| `failures` | Безопасные категории ошибок транспорта; без номера поколения и без необработанного текста |
| `send(command, connectionEpoch: epoch)` | Проверка актуальности и отправка типизированной команды |

Все потоки broadcast и не повторяют историю: подписываться нужно до connect.
Новый подписчик получает текущее состояние через getters, не через replay потока.
`updates` содержит в том числе уже неактуальные события с их исходными номерами;
если подписчик выполняет действие, он обязан проверить `isCurrent`.
Нельзя трактовать `failures` как подтверждение результата конкретной попытки входа:
для этого используются номер поколения, состояние соединения и события протокола.
Потоки могут содержать приватные данные: безусловное логирование запрещено.

Некорректный URI и повторный connect без отключения вызывают синхронное исключение
и не расходуют номер. Ошибка или отмена уже принятого handshake расходует номер.
Disconnect немедленно делает поколение неактивным; новый connect разрешается
после завершения очистки. Следующая попытка получает новый номер, даже для того
же адреса. Dispose немедленно инвалидирует поколение, затем асинхронно освобождает
ресурсы; доставка терминального события после dispose не обещается.

`send` требует не только актуального номера, но и подключённого транспорта:
при connecting ранний challenge можно обработать, но отправлять ещё нельзя.
Успех send не означает принятия команды сервером. Очереди команд нет.

## Порядок и защита от запоздалых ответов

`RoomRouter.updates` объединяет статусы и декодированные события, сохраняя порядок
исходного transport.updates. До публикации события маршрутизатор применяет его
к реестру комнат. Прежние потоки RoomRouter сохраняются для существующих клиентов.

Сессия отдельно считает принятые попытки (для синхронной проверки send) и смены
поколения в упорядоченном входящем потоке (для маркировки событий). Поэтому событие,
которое ещё находится в очереди обработки, не получает номер нового подключения.
Устаревшие callbacks физического сокета дополнительно отсеивает транспорт.

HTTP-контроллер захватывает номер **до** асинхронного запроса:

```dart
final epoch = challengeUpdate.connectionEpoch;
final challenge = challengeUpdate.event as ChallengeEvent;
final response = await authApi.login(challstr: challenge.challenge, /* ... */);
if (!session.isCurrent(epoch)) return;
session.send(
  TrnCommand(username: response.username, assertion: response.assertion),
  connectionEpoch: epoch,
);
```

Это схема интеграции. Номер соединения не заменяет
ID попытки входа и проверку текущего challenge: новый challenge может прийти в том
же соединении. Эти проверки выполняются [AuthController](auth-controller.md)
по auth-contract.md. Он также использует source sequence, чтобы не принимать
уже полученный до `/trn`, но задержавшийся в очереди updateuser.

## Проверки

Тесты с управляемым каналом проверяют порядок и номера событий, ранний challenge,
запрет отправки старого результата, смену сокета, ошибку/отмену handshake,
независимых подписчиков и завершение владельца. Тесты существующего контроллера
и экрана сохраняют сценарий одной комнаты на русском и английском.

Запуск: `flutter test --concurrency=1`. Публичный сервер и аккаунт для этих тестов
не используются. Этот рефакторинг не доказывает работоспособность HTTP-авторизации.
